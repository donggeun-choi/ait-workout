# 커뮤니티 실행과 운영 경계

공개 운동 인증은 개인 기기 기록과 독립된 서버 스냅샷이다. 로그인해도 기기 간 개인 기록을 동기화하지 않는다. SQLite를 사용하므로 서버 파일을 지속 보관하는 단일 인스턴스가 필요하다. 여러 서버에 서로 다른 SQLite 파일을 두면 같은 커뮤니티가 되지 않는다.

## 로컬 개발

```sh
bash scripts/setup.sh
bash scripts/dev-community.sh
```

다른 터미널에서 다음을 실행한다.

```sh
VITE_COMMUNITY_DEV_AUTH=true bash scripts/dev.sh --host 127.0.0.1
```

API 기본 포트는 5194이고 Vite는 `/api/community`를 프록시한다. 개인 기록만 확인할 때는 API 없이 기존 `dev.sh`를 실행해도 된다. 이때 커뮤니티는 연결 오류와 재시도를 표시한다. 개발 로그인은 명시적으로 켠 개발 서버의 loopback 요청만 허용하고 화면에 테스트 계정이라고 표시한다. 운영 빌드에는 해당 로그인 경로가 활성화되지 않는다. 데이터베이스는 무시되는 `data/community.sqlite`에 생성한다.

검증은 별도 Vite 포트와 브라우저 프로필을 사용한다. 별도 API도 필요하면 `COMMUNITY_PORT`, `COMMUNITY_DB_PATH`를 지정하고 Vite의 `COMMUNITY_PROXY_TARGET`을 맞춘다. `COMMUNITY_ALLOWED_ORIGINS`에 검증 화면 origin을 추가한다. 사용자의 현재 운동 저장소와 운영 DB를 테스트용 데이터로 덮어쓰지 않는다.

## 운영 연결

운영 서버에는 Node 24 이상, 영속 볼륨과 HTTPS 역방향 프록시가 필요하다. 서버의 환경 설정 예시는 `server/.env.server.example`, 클라이언트는 저장소 루트 `.env.example`을 따른다. 서버 환경은 런타임에서 주입한다. 인증서·운영 토큰을 프런트엔드의 `VITE_*` 변수에 넣지 않는다.

토스 로그인은 클라이언트 `appLogin` 결과의 authorizationCode/referrer를 서버로 전달하고, 서버가 공식 mTLS 토큰 발급·사용자 조회 API로 검증한다. 토스 이름·연락처·운동 메모를 받아 피드에 넣지 않는다. 서버는 토스 토큰을 영구 저장하지 않으며 별도의 만료되는 서비스 세션을 발급한다.

운영 실행은 `npm run start:community`다. mTLS 인증서/키, 명시적인 공개 활성화, 관리자 토큰, 공개 개인정보 안내 URL, 운영 연락처, 토스 탈퇴 콜백 인증과 관리자 화면의 정확한 HTTPS 출처(`COMMUNITY_ADMIN_ORIGIN`)를 갖추지 않으면 시작을 거부한다. 클라이언트의 `VITE_COMMUNITY_API_URL`은 `https://서버/api/community` 전체 경로로 설정해 빌드한다. 서버 origin 허용 목록에 실제 미니앱 origin을 정확히 등록한다. 와일드카드 CORS나 임의 사용자 ID 로그인은 사용하지 않는다.

콘솔 로그인 약관·콜백 설정, 인증서 발급, 호스팅 계정 생성·배포, 운영 광고 ID 발급은 이 코드의 로컬 테스트로 대신할 수 없다. 담당자가 정해지고 안내 내용이 실제 운영 방식에 맞게 확정된 뒤 공개 운영을 켠다.

## 신고 처리

`/api/community/admin-ui`는 운영자가 토큰을 입력해 신고를 읽고 숨김·복구·계정 제한·해제·처리 완료를 수행하는 별도 관리 화면이다. 데이터 API는 모든 요청에 운영 토큰을 검사하며 토큰은 화면 메모리에만 보관한다. 사용자 소감을 HTML로 실행하지 않는다. 이 화면은 개인 기기의 비공개 운동 기록을 읽을 수 없다.

운영 토큰은 비밀 관리자 자격 증명이다. 접근자를 제한하고 교체하며, 관리 화면의 접근을 역방향 프록시에서 추가로 제한할 수 있다. SQLite 파일·백업에도 서버와 동일한 접근 제한을 적용한다. 신고 처리 이력은 감사 API에서 확인한다. 신고 수만으로 자동 삭제하지 않는다.

기본 신고·감사 로그 보관은 30일이며 `COMMUNITY_RETENTION_DAYS`로 1~365일 중 명시한다. 서버는 시작 및 매시간 만료 로그를 정리한다. 이 숫자는 법적 준수를 보장하는 값이 아니라 구현 기본값이다. 운영자가 실제 고지·처리 목적에 맞게 설정한다. 탈퇴는 게시·응원·차단·서비스 세션을 제거하고 보관 로그의 계정 연결을 익명화한다. 개인 기기 기록 삭제는 앱의 데이터 관리에서 별도로 선택한다.

토스 콘솔의 탈퇴 콜백은 `/api/community/auth/withdrawal-callback`으로 등록하고 서버의 Basic 인증 값과 맞춘다. 콘솔 테스트용 userKey=0 요청은 실제 사용자 삭제 없이 수신 확인한다. 서버 탈퇴 이후 토스 연결 해제 실패 시 앱은 별도 연결 해제를 안내한다.

## 백업과 복구

서비스 DB는 개인 JSON 백업과 다른 자료다. 서버 DB 백업은 SQLite의 일관된 백업 방식이나 정지 상태 복사를 사용한다. 실행 중 `.sqlite` 파일 하나만 임의로 복사하면 WAL 변경이 누락될 수 있다. 실제 운영에서는 DB 복원·세션 만료·계정 삭제와 보관 로그 정책을 함께 검증한다. 현재 구현은 서버 DB의 자동 원격 백업이나 고가용성을 제공하지 않는다.
