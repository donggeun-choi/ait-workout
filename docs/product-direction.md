# 운동노트의 역할과 개발 기조

## 앱이 하는 일

운동노트는 Apps in Toss에서 사용하는 개인 운동 기록 미니앱이다. 사용자는 자유 운동 또는 준비된 루틴으로 운동을 시작하고, 종목별 세트의 무게·횟수를 입력해 완료 여부를 기록한다. 운동을 마친 뒤 기록을 저장하고 홈과 대시보드에서 활동과 변화를 확인한다.

Strong의 세트 기록, 루틴, 휴식 타이머, 통계 흐름을 참고한다. 구현의 중심은 토스 환경에 맞는 간결한 기록 경험과 TDS 컴포넌트다. 앱 이름은 임시 이름인 운동노트다.

## 핵심 사용자 흐름

1. 홈에서 이번 주 활동과 최근 기록을 확인한다.
2. 운동 탭에서 자유 운동을 준비하거나 별도 루틴 선택 화면에서 상체·하체·전신 루틴을 선택한다.
3. BottomCTA로 운동을 시작한다.
4. 종목을 검색·추가하고 세트별 무게·횟수를 입력한 뒤 완료를 체크한다. 필요하면 휴식 타이머와 메모를 사용한다.
5. 운동을 마치고 완료한 세트를 저장한다.
6. 홈에서 기록 상세를 보고 대시보드에서 기간별 활동·운동량·최고 세트 무게를 확인한다.

## 화면별 책임

| 화면 | 사용자의 목적 | 구성 원칙 |
| --- | --- | --- |
| 홈 | 최근 운동과 이번 주 활동을 빠르게 확인 | 기록이 없으면 정직한 빈 상태, 최근 기록에서 상세로 연결 |
| 운동 준비 | 오늘 할 운동을 결정하고 시작 | 선택된 운동 구성을 보여주고 시작 행동은 BottomCTA 하나로 명확하게 표현 |
| 루틴 선택 | 추천 루틴을 비교하고 선택 | 별도 화면에서 단일 선택, 구성 미리보기, 확정과 취소를 구분 |
| 운동 진행 | 운동 중 최소한의 조작으로 기록 | 무게·횟수·완료 상태가 중심, 수정과 세트 추가가 쉬워야 함 |
| 대시보드 | 기록의 변화와 추이를 이해 | 기간과 계산 기준이 명확한 실제 기록 기반 통계 |

하단 내비게이션은 홈·운동·대시보드 3개다. 루틴 선택은 운동 탭의 하위 화면이며 독립 탭으로 늘리지 않는다. 플랫폼 상단 내비게이션을 직접 재현하지 않는다.

## 개발 기조

### 기록의 신뢰성을 먼저 지킨다

기록 입력과 저장은 앱의 중심 기능이다. 진행 중인 운동은 새로고침 후 복원돼야 하고 저장 실패는 사용자가 알아보고 재시도할 수 있어야 한다. 읽을 수 없는 기존 데이터를 임의로 덮어쓰지 않는다. 저장 형식을 바꿀 때는 기존 데이터의 호환·복원 경로를 함께 검토한다.

통계는 저장된 완료 세트를 기준으로 계산한다. 예시 보기 데이터는 실제 기록과 통계에 섞이지 않는다. 검증은 별도 브라우저 프로필이나 로컬 포트를 사용해 사용자 기록을 보호한다.

### 운동 중 빠르게 쓸 수 있게 만든다

변경의 가치는 사용자가 운동을 시작하거나 세트를 기록하는 데 필요한 조작이 줄고, 상태가 더 쉽게 이해되는지로 판단한다. 준비 화면과 진행 화면의 역할을 구분하고, 루틴 탐색이 기록 입력을 방해하지 않게 한다. 버튼 이름에는 실제 결과를 담는다.

### TDS를 의미에 맞게 사용한다

TDS 컴포넌트를 기본으로 하고 설치된 타입이나 공식 문서에서 API를 확인한다. 시작·저장 같은 화면의 주요 행동은 BottomCTA, 선택 항목은 선택 상태가 명확한 목록, 설명은 보조 텍스트로 표현한다. 기능이 없는 장식 요소를 클릭 가능하게 만들지 않는다.

브랜드 primary는 사용자가 지정한 토스 blue(`#3182F6`)다. 본문·보조 정보·제목의 크기는 각 요소의 역할에 맞춰 정한다. 큰 아이콘이나 반복되는 강조 카드로 화면을 채우지 않는다. 아이콘의 시각 크기와 터치 영역은 따로 다룬다. 구체적 크기는 `workout-screen-design.md`, 플랫폼 제약은 `design-guide.md`를 따른다.

### 작은 변경을 끝까지 검증한다

각 화면을 단계적으로 개선한다. 변경 전에 화면의 목적과 문제를 설명하고, 변경 후 모바일 캡처와 실제 조작으로 해결 여부를 확인한다. 기능 변경은 관련 저장·복원·조회 흐름까지 확인하고 전체 검증 스크립트를 실행한다. 문서만 변경한 경우에는 링크·내용·차이를 확인하며 불필요한 앱 빌드를 반복하지 않는다.

추상화나 의존성은 반복되는 문제를 해결할 때 도입한다. 새 기능은 현재 기록 흐름과의 관계, 필요한 데이터, 실패 상태가 명확해진 뒤 구현한다. 계정·동기화·결제·광고 같은 범위 확대는 별도 제품 결정으로 다룬다.

## 현재 지원 범위와 제한

- React DOM, TypeScript, Vite와 TDS 기반이며 데이터는 기기 브라우저의 `localStorage` 키 `workout-log-v1`에 저장한다.
- 추천 루틴은 고정 템플릿이다. 사용자 루틴 생성·편집, 로그인, 기기 간 동기화는 아직 구현하지 않았다.
- 완료 체크한 세트만 완료 기록에 저장한다. 운동량은 완료 세트의 무게 × 횟수 합이며 입력 무게가 0인 맨몸 운동의 운동량은 0으로 계산한다.
- 웹 검증과 `.ait` 빌드는 제공한다. 실제 토스 앱의 키보드·뒤로가기·safe area 동작은 기기 검증이 필요하다.

## 변경 전 확인할 질문

- 사용자가 어느 화면에서 어떤 일을 더 쉽게 하게 되는가?
- 기존 시작 → 세트 입력 → 저장 → 조회 흐름과 기록 데이터는 유지되는가?
- 해당 요소의 역할을 표현하는 TDS 컴포넌트가 있는가?
- 빈 상태, 취소, 입력 오류, 저장 실패에서도 다음 행동이 명확한가?
- 현재 구현 범위와 문서가 일치하는가?

이 문서는 현재 제품 방향의 기준이다. 범위가 바뀌면 코드와 함께 갱신한다.
