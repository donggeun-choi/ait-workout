# 운동노트 제품 설계 — 빠른 기록과 운동 인증·응원

2026-10-01 · Superpowers brainstorming

대화에서 합의한 제품 설계다. 구현 계획과 구분한다. 현재 앱은 3탭·로컬 운동 기록이며 아래의 4탭·서버 커뮤니티·토스 로그인은 개발할 목표다.

## 1. 목적과 합의

정해진 루틴을 반복하는 운동자가 지난 값을 활용해 빠르게 세트를 기록하고, 선택적으로 운동을 인증하고 응원받아 다음 운동을 이어가게 한다. 개인 기록의 정확성·보존을 우선한다.

사용자가 확정한 사항:

- 핵심 사용자: 정해진 루틴을 반복하는 운동자.
- 커뮤니티 목적: 운동 인증과 응원. 공개 범위는 앱 사용자 전체.
- 인증 방식: 저장한 운동 기록과 선택적인 한 줄 소감. 사진 제외.
- 하단 탭: 홈·운동·대시보드·커뮤니티 4개.
- 개인 기록과 피드 읽기는 로그인 없이 제공. 게시·응원·신고·차단을 처음 사용할 때 토스 로그인.
- 개인 기록과 공개 게시물을 분리. 로그인 취소·게시 실패는 기록 저장에 영향을 주지 않는다.
- 초기 광고는 대시보드 통계 아래 배너 1개. 운동·휴식·저장·인증 작성은 광고 없음.
- TDS를 컴포넌트 역할에 맞게 사용한다.

성공은 기능 수보다 운동 시작·반복 입력의 조작 감소, 저장 신뢰성, 인증 후 응원과 다음 운동으로의 복귀로 판단한다. 매출·사용자 수·전환율 목표는 운영 데이터 없이 예측하지 않는다.

공개 자료 조사만으로 인아웃·자리톡의 현재 토스 미니앱 커뮤니티 화면·광고 위치는 검증하지 못했다. 해당 서비스의 일반 앱 기능을 미니앱 기능으로 간주하지 않는다. 현재 문서는 확인된 운영 사례에서 제품 원칙을 도출한 설계다. 실제 화면 비교는 추가 벤치마킹 항목이며 이를 완료했다고 표시하지 않는다.

## 3. 범위와 개발 묶음

| 묶음 | 포함 | 사용자 가치 |
| --- | --- | --- |
| 기록 신뢰성 | 저장 상태, 이어하기, 실패 재시도, 초안 복원 | 기록 유실 불안 감소 |
| 반복 기록 | 지난 값 표시, 최근 운동 다시 하기, 내 루틴, 순서 이동, 휴식 설정 | 매번 검색·입력 감소 |
| 기록 관리 | 기록 수정·삭제, 통계 재계산 | 입력 실수 수정 |
| 커뮤니티 첫 버전 | 공개 피드, 인증, 응원, 내 인증, 로그인, 신고·차단·삭제, 운영 처리 | 기록을 통한 가벼운 상호 응원 |
| 광고 운영 검증 | 대시보드 슬롯 지원·노필·복귀·제거 검증 | 기록 흐름 보호와 수익화 |

사진·댓글·팔로우·채팅·랭킹·그룹·포인트·전면/보상 광고는 첫 버전에서 제외한다. 백업·복원·종목 추이는 후속 기록 기능이다. 커뮤니티 로그인은 기기 간 운동 기록 동기화를 의미하지 않는다.

커뮤니티는 서버·인증·운영 기능이 묶인 별도 하위 프로젝트다. 기록 개선부터 진행하며 서버 없는 모형을 실제 커뮤니티처럼 출시하지 않는다. 각 묶음의 구현 계획과 검증을 분리한다.

## 4. 화면과 행동

### 홈

주간 활동·최근 기록·운동 이어하기가 중심이다. 초안이 있으면 이어하기를 주 행동으로 둔다. 커뮤니티 진입을 위해 운동 시작을 밀어내는 큰 카드나 자동 팝업을 추가하지 않는다.

### 운동 준비와 진행

준비 화면에서 최근 운동·내 루틴·추천 루틴·자유 운동을 선택하고 BottomCTA로 시작한다. 최근 운동 복사는 종목 순서·값·세트 구성을 초기값으로 사용하되 완료 상태·날짜·메모는 초기화한다. 원본 기록과 참조를 공유하지 않는다.

진행 화면은 무게·횟수·완료를 중심으로 유지한다. 지난 완료 기록은 보조 정보다. 같은 값의 다음 세트 완료는 1탭이며 확인창이 없다. 세트 추가는 직전 유효값을 복사한다. 입력을 이미 수정했으면 최근 값이 자동 덮어쓰지 않는다.

내 루틴은 이름·종목 1개부터 생성하며 기본 세트·휴식 설정을 제공한다. 루틴 변경은 진행 초안과 과거 기록을 바꾸지 않는다. 종목 순서는 위/아래 이동으로 조절한다. 휴식은 60/90/120초·끄기, +30초·건너뛰기를 제공하며 입력을 막지 않는다.

저장 중/저장됨/저장 실패를 구분한다. 완료 저장이 성공해야 결과 화면으로 이동한다. 입력 실패·손상 데이터·읽기 실패에서 원본을 보존한다. 기록 편집은 복사본을 저장해 확정하고 실패 시 원본을 유지한다.

### 완료 결과와 인증 작성

완료 결과의 주 행동은 홈 복귀다. 보조 행동 `운동 인증하기`로 별도 작성 화면에 진입한다. 공유를 요구하는 팝업은 없다. 과거 기록 상세에서도 인증할 수 있다.

로그인이 필요하면 작성 진입에서 요청한다. 취소하면 완료 결과로 돌아가며 운동 기록은 유지된다. 인증 작성 중 로그인 만료는 입력을 보존하고 재로그인을 제공한다. 공개되지 않은 작성 내용은 피드에 노출하지 않는다.

게시물 기본 필드: 서비스 닉네임, 운동 날짜, 종목 수, 완료 세트 수. 한 줄 소감은 선택이며 최대 100자(사용자에게 보이는 문자 기준)다. 종목명·무게·횟수 공개는 각각 기본 꺼짐이다. 무게·횟수만 공개해도 종목명을 추정할 수 있으므로 공개 미리보기로 실제 공개 내용을 확인한다. 개인 메모·총 운동량·상세 시각은 자동 공개하지 않는다.

공개 안내는 `앱 사용자 누구나 볼 수 있어요`. 게시 CTA는 `인증 올리기`. 닉네임은 실제 토스 이름을 공개 기본값으로 사용하지 않는다. 처음 게시할 때 서비스 닉네임을 설정하고 운영 정책에 동의한다. 닉네임은 2~12자로 제한하고 개인정보·연락처 포함을 피하도록 안내한다.

운동당 활성 인증은 1개. 중복 게시 시 기존 내 인증으로 연결한다. 요청 중에는 동일 제출만 막고 뒤로가기는 허용한다. 게시 성공 후 커뮤니티의 내 게시물로 이동한다. 실패 시 작성값을 유지하고 재시도를 제공한다.

### 커뮤니티

최신순 피드와 내 인증을 화면 내부 TDS Tab으로 전환한다. 첫 페이지 20개와 `더 보기`로 추가 로딩하며 최신 데이터 확인은 명시적인 새로고침으로 한다. 읽는 중 자동 삽입으로 스크롤 위치를 바꾸지 않는다.

게시물은 닉네임·운동 날짜·요약·선택 공개값·소감·응원 수·응원 버튼·더보기로 구성한다. 응원은 계정당 게시물 1개, 재탭하면 취소. 자기 게시물에는 응원할 수 없다. 응원 수로 피드를 정렬하지 않으며 경쟁성 배지·순위를 만들지 않는다.

피드 빈 상태는 `아직 운동 인증이 없어요`와 운동 기록으로 연결한다. 가짜 게시물·응원 수를 만들지 않는다. 로딩 오류는 재시도, 오프라인은 현재 로드된 게시물과 연결 안내를 제공한다. 로그인 없이 응원하면 로그인 후 같은 게시물의 동작을 이어가되 재확인 없이 다른 게시물에 실행하지 않는다.

내 게시물 메뉴: 삭제. 타인 게시물 메뉴: 신고·차단. 삭제는 결과를 확인하고 서버 성공 후 제거한다. 응원 실패는 원래 상태로 되돌리고 재시도를 안내한다. 작성/게시 실패가 개인 기록을 변경하지 않는다.

### 대시보드

완료 세트 기준 기간별 통계와 종목 최고 기록을 유지한다. 수정·삭제 후 동일 기준으로 재계산한다. 광고는 통계·저장 위치 안내 다음에 둔다.

## 5. TDS 사용 계약

| 역할 | 적용 기준 |
| --- | --- |
| 제목·소개 | Top, Paragraph 계열. 과대한 제목과 중복 안내 제거 |
| 기록·루틴·설정 목록 | ListHeader, ListRow, ListRow.Texts, Border |
| 시작·저장·게시 | BottomCTA.Single. 화면마다 주 행동 1개 |
| 보조 행동·응원 | Button. 상태·비활성·처리 중 표시 일관성 |
| 피드/내 인증·기간 선택 | 설치된 TDS Tab 등 적합한 선택 컴포넌트 |
| 소감·닉네임 | 설치된 TDS 입력 API. 오류·길이 안내 포함 |
| 공개 옵션 | 설치된 TDS 선택/스위치 API 확인 후 사용 |
| 상태·아이콘 | Badge와 공식 제공 Asset 아이콘. 텍스트 화살표 금지 |
| 하단 4탭 | 설치된 TDS에 적합한 탭 내비게이션 API가 있으면 사용. 플랫폼 상단 네비 직접 재현 금지 |

모든 선택 컴포넌트는 설치된 타입을 확인한 후 결정한다. 커스텀 UI를 TDS처럼 보이게 만드는 것으로 충족하지 않는다. 색·타이포·크기를 컴포넌트 기본 역할에 맞추고 브랜드 primary는 #3182F6 유지. 카드·큰 아이콘으로 정보 위계를 대신하지 않는다.

세트 기록 표는 반복 숫자 입력에 적합한 TDS 구성 가능성을 먼저 검토한다. 터치 목표 44px, 16px 숫자 입력, 좁은 모바일에서 조작 유지가 충족되지 않으면 이 부분만 커스텀 입력을 사용하고 이유를 검증 보고에 남긴다.

본문 15px 이상, 11px 이하 금지, weight 400~700, Tossface, keep-all, safe area 최소 34px, 키보드·CTA·4탭 겹침 방지를 전 화면 확인한다.

## 6. 데이터 흐름과 시스템 경계

1. 기록 저장소: 현재 네이티브 Storage/웹 localStorage. 세션·초안·루틴·설정·저장 큐 담당.
2. 인증 연결: 클라이언트 로그인 결과를 서버에서 검증해 서비스 계정·세션으로 교환. 클라이언트가 보낸 사용자 ID만으로 작성 권한을 인정하지 않는다.
3. 커뮤니티 서비스: 게시물·응원·차단·신고·계정 정책 담당. 개인 기록 저장소 쓰기에 의존하지 않는다.
4. 광고 어댑터: 화면·초안·운영 설정으로 노출 여부 판단. 기록/게시 성공 여부에 광고 요청을 연결하지 않는다.

핵심 객체:

- User: 내부 ID, 닉네임, 계정 상태. 토스 로그인 식별 정보는 서버에서 관리하고 피드로 반환하지 않는다.
- Post: ID, 작성자 ID, 작성자 계정에 속한 원본 운동 키, 운동 날짜, 공개 요약 스냅샷, 공개 옵션, 소감, 게시 시각, 상태.
- Cheer: 게시물 ID와 사용자 ID의 고유 조합. 설정/해제 요청은 반복 호출해도 같은 결과.
- Block: 차단자·대상 계정 고유 조합. 로그인한 사용자의 피드·응원 표시에서 차단 대상 제외. 로그아웃하면 개인 차단 필터가 적용되지 않음을 안내.
- Report: 신고자·대상 게시물·사유·접수 시각·처리 상태. 같은 게시물 반복 신고는 중복 접수 방지.

게시 생성은 계정+원본 운동 키의 고유 제약과 요청 ID로 중복을 방지한다. 오프라인 기록은 사진·센서로 검증한 사실이 아니므로 인증을 실제 운동 수행의 보증으로 표현하지 않는다. 로컬 데이터가 조작될 수 있으며 첫 버전에 경쟁 보상을 두지 않는다.

공개 게시물은 원본의 복사본이다. 과거 기록 수정은 공개 스냅샷을 변경하지 않는다. 개인 기록 삭제 전 활성 인증 연결이 확인되면 공개 인증은 별도로 남는다고 안내한다. 인증 삭제는 원본 운동을 삭제하지 않는다. 삭제한 원본과 활성 인증의 연결 키는 중복 방지용으로 유지한다. 로그인 계정 변경 시 다른 계정의 작성 상태를 노출하지 않는다.

회원 탈퇴 시 공개 게시물·응원·차단을 제거하고, 개인 기기 기록 삭제는 별도로 선택한다. 신고·운영 로그의 보관은 출시 전 고지한 정책에 따라 제한한다. 커뮤니티 출시 전에 구체적인 보관 기간과 개인정보 처리 안내를 확정해야 한다. 이는 현재 지원 기능이 아니다.

## 7. 공개 커뮤니티 운영

신고 사유: 욕설·혐오, 광고·도배, 개인정보 노출, 기타. 신고 즉시 신고자의 화면에서 해당 게시물을 숨긴다. 누적 신고 수만으로 자동 삭제하지 않는다. 차단은 서버 피드 필터에 반영하며 차단 관리 화면에서 해제한다.

운영자는 제한된 관리 화면에서 신고 대기 목록·게시물 맥락을 확인하고 숨김/복구/계정 제한을 처리한다. 운영 권한은 서버에서 검사하고 처리 이력을 남긴다. 운영자가 일반 계정으로 타인의 개인 운동 기록을 조회하는 기능은 없다.

작성·응원·신고에는 서버 속도 제한과 본문 길이 검증을 둔다. 사용자 소감은 텍스트로 렌더링하고 HTML을 실행하지 않는다. 게시 실패와 삭제된 게시물·제한된 계정·인증 만료를 구분한다. 운영 처리 담당자와 개인정보 보관 정책이 준비되지 않으면 공개 커뮤니티를 운영 활성화하지 않는다.

## 8. 광고 정책

초기 슬롯: 대시보드 통계·안내 아래 스크롤 배너 1개. 실제 기록 1개 이상, 초안 없음, 예시 아님, SDK 지원·초기화 성공·운영 ID 있음일 때만 부착한다.

운동 준비·진행·휴식·저장·결과 시트·인증 작성·기록 편집에는 광고 없음. 첫 진입의 주요 콘텐츠를 밀지 않으며 탭바 아래 고정하지 않는다. 광고 클릭은 응원·게시물 버튼의 영역과 겹치지 않는다.

SDK가 광고 표시와 갱신을 관리한다. 미지원·노필·실패는 슬롯 제거, 이탈은 destroy, 중복 초기화/부착 방지. 광고 요청 실패가 앱의 핵심 로딩 상태가 되지 않는다. 커뮤니티 광고·전면·보상형은 미구현 후속 실험으로만 기록한다.

공식 기준: [WebView 배너](https://developers-apps-in-toss.toss.im/documentation/common/monetization/iaa/web-banner). 콘솔 설정·약관 확인·운영 활성화·배포는 별도 작업이다.

## 9. 검증과 출시 조건

기록 흐름:

- 60kg×8회 완료 → 480kg → 재진입 복원 → 저장 → 홈/대시보드 일치.
- 0회 입력 차단, 미완료 세트 제외, 직렬 저장, 쓰기·읽기·이관 실패 원본 보호.
- 다시 하기는 완료 상태 초기화·원본 독립. 루틴/기록 수정과 취소 검증.
- 입력 중 타이머·햅틱·네트워크 요청이 포커스·스크롤·완료를 막지 않음.

커뮤니티 흐름:

- 로그인 없이 기록·피드 읽기. 로그인 취소·만료·게시 실패 후 개인 기록 유지.
- 기본 공개값 미리보기 일치. 비공개 무게·횟수·메모는 서버 요청과 피드 응답에 포함되지 않음.
- 중복 제출·네트워크 재시도에도 게시물 1개. 사용자당 응원 1개, 자기 응원 금지.
- 타인 게시 삭제 불가. 신고·차단·해제·운영 숨김·탈퇴의 서버 권한 검증.
- 기록 수정·삭제와 인증 삭제가 의도한 독립성을 유지.
- 빈 피드·로딩 실패·오프라인·삭제된 게시물에서 다음 행동 제공.

화면/광고:

- 320px·390px 및 실기기 iOS/Android에서 4탭·키보드·CTA·시트·안전 여백 확인.
- TDS 기본 스타일을 강제 재정의한 부분과 커스텀 입력 예외를 검토.
- 초안 존재 시 광고 0개. 노필·클릭 복귀·탭 이탈·게시 화면 이동 검증.
- SDK·광고·분석 실패가 기록 입력·저장 실패로 전파되지 않음.

측정 항목: 시작까지 조작 수, 반복 세트 완료 조작 수, 저장 실패/재시도 결과, 저장→인증 작성→게시 전환, 인증당 응원, 인증 사용자의 다음 운동 방문, 광고 전후 기록 완료 흐름. 분석에 소감·메모·상세 운동값을 보내지 않는다. 로그인을 통한 사용자 지표는 동의·고지와 최소 수집 정책을 맞춘 뒤 사용한다.

## 10. 구현 계획에서 확정할 사항

서버 공급자·DB·호스팅, 토스 로그인 서버 연동 설정, 관리자 계정, 신고 처리 담당자, 개인정보 보관 기간은 아직 운영 선택이 없다. 임의로 계정·외부 프로젝트를 생성하지 않는다. 이 항목들은 구현 계획과 출시 준비에서 정하며 지금 확정된 사용자 흐름과 공개 정보 범위를 바꾸지 않는다.

각 구현 계획은 기록 개선 / 커뮤니티 서버·운영 / 커뮤니티 TDS 화면 / 광고 운영 검증으로 나눠 검토한다. 이 문서 승인 전 제품 코드 구현은 진행하지 않는다.
