# 운동 화면의 정보 위계

## 최근 운동 재사용 (2026-10-03)

운동 준비의 선택 구성 아래 실제 최근 기록 최대 3개를 TDS ListRow 단일 선택 목록으로 표시한다. 자유 운동 항목으로 선택을 해제할 수 있다. 종목·완료 세트 수를 미리 확인하고 하단 고정 CTA `지난 운동 다시 시작`으로 확정한다. 최근 운동 선택과 추천 루틴 선택은 동시에 적용하지 않는다. 루틴 선택 화면에서 취소하면 기존 최근 운동 선택을 유지한다.

복사하는 것은 완료 세트의 무게·횟수·종목 순서다. 완료 상태·메모·휴식은 초기화하고 시간과 ID는 새로 만든다. 실제 기록만 사용하며 예시 데이터는 재사용 목록에 포함하지 않는다. 진행 초안이 있으면 준비 목록 대신 기존 운동을 이어간다.

진행 제목 아래 15px 저장 상태를 표시하며 입력 재마운트와 포커스 변경 없이 갱신한다. 오류 재시도는 현재 입력을 저장하고 완료 저장 성공 전에는 결과 시트를 표시하지 않는다.

운동 메인의 역할은 시작할 운동을 확인하고 시작하는 것이다. 루틴 탐색·선택은 별도 화면으로 분리한다.

| 요소           | 의미                | 표현                                         |
| -------------- | ------------------- | -------------------------------------------- |
| 화면 제목      | 현재 위치           | TDS Top, 20px, 짧은 명사형                   |
| 시작할 운동    | 다음 행동의 대상    | 일반 요약 영역, 운동 이름 18px               |
| 종목과 세트 수 | 시작 전 확인할 내용 | 본문 15px, 목록 이름 15px                    |
| 루틴 변경      | 다른 화면으로 이동  | TDS ListRow, 15px, 이동 화살표               |
| 루틴 목록      | 한 가지 선택        | TDS ListRow, 단일 선택 역할과 원형 선택 표시 |
| 운동 구성      | 선택 결과 확인      | 종목 15px, 세트 수 15px, 번호 13px           |
| 하단 CTA       | 실제 실행           | 자체 하단 고정 CTA, 대상이 포함된 동사형 문구     |

요약 자체는 클릭할 수 없다. 요약 안의 ‘추천 루틴에서 선택’ 또는 ‘루틴 변경’만 이동한다. ‘선택됨’ 배지를 여러 곳에 붙이지 않는다. 큰 질문형 제목과 중복 설명을 제거해 운동 내용과 실행 버튼을 우선한다.

루틴 화면에서는 선택과 확정을 분리한다. 바뀐 선택의 종목 구성을 바로 보여 주고 하단 CTA로 확정한다. 돌아가기로 나가면 기존 선택은 유지된다. 라디오 역할과 방향키 조작을 제공한다.

본문의 최소 크기를 유지하면서 화면 제목 22px → 운동 이름 18px → 목록 제목 17px → 본문 15px → 보조 라벨 13px로 역할을 구분한다. 기존 기록은 바꾸지 않는다.

## 인터랙션

- 탭·루틴 화면 이동과 운동 시작은 220ms의 작은 이동(6px), 크기 변화(98.5% → 100%)와 페이드로 위치 변화를 알려준다. Web Animations API로 콘텐츠에만 적용하고 탭바·BottomCTA는 고정한다. 콘텐츠를 재마운트하지 않고 즉시 조작할 수 있다. 실제 레이아웃 높이를 바꾸지 않아 스크롤과 입력 위치를 유지한다.
- 바텀시트는 220ms로 들어오고 150ms로 나간다. 배경도 함께 변하며 닫힘이 끝날 때 내용과 모달을 정리해 빈 시트가 보이지 않게 한다.
- 닫기·Escape·배경 클릭은 같은 종료 흐름을 사용한다. 닫는 동안 종목 중복 추가를 막고 종료 후 기존 포커스를 복원한다.
- 세트 입력·완료, 타이머 갱신에는 화면 전환을 반복하지 않는다. 상태 색상만 120ms로 바뀐다.
- `prefers-reduced-motion: reduce`에서는 이동·페이드·상태 전환을 생략한다.

## 뒤로가기

플랫폼 상단 네비게이션의 뒤로가기 버튼을 설정하고 `graniteEvent.backEvent`를 연결한다. 처리할 시트나 내부 화면 이력이 없는 첫 화면에서는 이벤트를 구독하지 않아 플랫폼 기본 종료 동작을 유지한다.

- 시트가 열려 있으면 먼저 시트만 닫고 운동과 입력값을 유지한다. 브라우저 이력에도 시트 진입을 기록해 로컬 뒤로가기로 확인할 수 있다.
- 루틴 취소·확정은 이전 화면으로 복귀한다. 직접 루틴 URL로 진입한 경우에는 운동 화면으로 대체 이동한다. 취소한 임시 선택은 적용하지 않는다.
- 내부 화면 이력이 있으면 이전 화면으로 이동한다. 최초 이력에 화면 정보를 저장해 초기 화면으로 돌아갈 때 잘못 홈으로 바뀌지 않게 한다.
- 종료를 막는 반복 확인창이나 자체 상단 네비게이션은 추가하지 않는다.

공식 근거: [네비게이션 바 설정](https://developers-apps-in-toss.toss.im/documentation/common/navigationbar), [이벤트 제어하기](https://developers-apps-in-toss.toss.im/documentation/common/screen/event).

로컬 확인: 시트에서 브라우저 뒤로가기 → 시트 종료·포커스 복귀, 루틴 직접 진입 → 임시 선택 취소·운동 화면 복귀, 대시보드 → 뒤로가기 → 운동 입력 유지. 실제 토스 상단 버튼과 최초 화면 종료는 기기 확인이 필요하다.

## 운동 종목이 없는 진행 화면

큰 빈 상태 아이콘 대신 제목·한 줄 안내와 TDS ListRow 추천 목록 최대 3개를 표시한다. 실제 최근 기록의 종목을 최신 순으로 중복 없이 우선하고, 부족한 자리는 벤치 프레스·랫 풀다운·스쿼트 목록으로 채운다. 예시 데이터는 추천에 사용하지 않는다. 추천은 현재 카탈로그에 있는 종목만 제공하며 의료·트레이닝 처방을 의미하지 않는다.

목록은 종목 이름·부위·작은 추가 아이콘만 표현한다. 누르면 시트나 확인 절차 없이 종목 1개와 기존 기본 세트를 추가하고 기록 화면으로 전환한다. 첫 종목 추가 이후 추천 영역은 사라진다. 다른 종목 검색은 하단 BottomCTA ‘다른 운동 찾기’ 하나로 제공한다. 종목이 없는 동안 빈 메모 입력과 저장 안내를 숨기되 기존 메모가 있으면 유지한다. 종목을 추가하면 메모·추가 버튼·완료 저장 CTA를 표시한다.

## 스크롤 경계

앱은 100dvh 안에서 콘텐츠 main만 스크롤한다. CTA와 탭바의 높이를 제외한 공간을 main에 할당하므로 입력·메모·마지막 안내가 고정 UI 뒤에 숨지 않는다. 공통 네비게이션 높이 변수는 TDS 포털에서도 읽을 수 있도록 루트에 둔다. 화면 이동 시 main의 스크롤을 초기화한다. 시트는 안전 영역을 제외한 최대 높이 안에서 독립적으로 스크롤하며 배경으로 스크롤을 전달하지 않는다. 숫자 입력과 메모는 16px로 유지해 iOS 입력 확대를 피한다.

## 추천 테마

운동 준비 화면에는 등·가슴·하체·푸시데이·풀데이 이름만 작은 버튼으로 보여준다. 종목이 없는 진행 화면에서는 ‘추천 테마로 구성하기’를 펼쳐 접근한다. 테마 선택은 별도 루틴 화면의 임시 선택으로 연결되며, 구성 확인 후 확정한다. 진행 중인 종목이 있으면 테마 바로가기는 표시하지 않아 기존 운동을 덮어쓰지 않는다. 빈 운동에 테마를 적용하면 시작 시각과 메모는 유지하고 종목 구성만 채운다.

| 테마 | 기본 종목 |
| --- | --- |
| 등 | 랫 풀다운, 시티드 로우 |
| 가슴 | 벤치 프레스, 인클라인 덤벨 프레스 |
| 하체 | 스쿼트, 레그 프레스, 루마니안 데드리프트, 크런치 |
| 푸시데이 | 벤치 프레스, 인클라인 덤벨 프레스, 숄더 프레스, 트라이셉스 푸시다운 |
| 풀데이 | 랫 풀다운, 시티드 로우, 덤벨 컬 |

기존 상체·전신 루틴도 유지한다. 각 종목의 기본 3세트·무게·횟수는 기록 시작 후 수정할 수 있다. 개인 맞춤 운동 처방이 아닌 기록용 고정 템플릿이다. 선택 목록과 방향키 이동은 루틴 개수에 맞춰 동적으로 생성한다.

## 운동 화면 리디자인 (2026-10-03)

이 절은 적용한 운동 준비·진행 디자인이다. [적용 계획](superpowers/plans/2026-10-03-workout-screen-redesign.md)을 따른다.

### 목적과 참고

운동 중 현재 세트의 무게·횟수를 빠르게 입력하고 완료하며, 지난 운동의 대응 세트를 같은 위치에서 참고한다. 최신 사용자 요청에 따라 진행 화면은 앱 전체와 같은 흰 배경·연한 회색·blue `#3182F6`를 사용한다. 입력·메모·관리·하단 CTA는 자체 컴포넌트를 사용한다.

- [Pinterest: Kenko / Vitaly Rubtsov](https://www.pinterest.com/pin/771663717392901292/): 종목 선택 목록과 정보 구분을 참고한다.
- [Pinterest: Strong exercise details & feedback](https://www.pinterest.com/pin/339881103143129365/): 현재 운동과 주요 행동의 위계를 참고한다. 영상·신체 이미지 중심 구성은 도입하지 않는다.
- [Hevy 공식 운동 기록 화면](https://www.hevyapp.com/wp-content/uploads/image-2-768x785.png): 대응하는 지난 세트·현재 입력·완료 상태의 근접 배치를 참고한다.

위 자료는 시각적 참고이며 조작 속도에 대한 검증 근거는 아니다. 실제 적합성은 아래 모바일 검증으로 확인한다.

### 진행 화면

1. 운동 이름과 저장 상태를 표시하고, 경과 시간·완료 세트/전체 세트를 간결한 한 줄에 둔다. 총 운동량은 입력 화면의 상단에서 제외하고 저장 결과·분석에서 확인한다.
2. 기본 휴식 선택과 타이머를 하나의 예약된 영역에 둔다. 휴식 중에는 남은 시간·+30초·건너뛰기, 종료 시에는 종료 안내·+30초·닫기를 제공한다. 대기·끄기 상태도 같은 높이를 사용하며 320px에서도 모든 상태가 같은 한 줄 배치를 사용한다. 타이머는 자동으로 화면을 가리거나 입력 위치를 옮기지 않는다.
3. 종목 이름·부위·완료/전체 세트와 `종목 관리`를 표시한다. 관리 영역은 기본 접힘이며 펼쳤을 때만 빈 입력에 지난 값·위/아래 이동·삭제를 제공한다. 본문 안의 접힘 영역으로 구현하여 모달·페이지 이동을 추가하지 않는다.
4. 세트 표는 세트·kg·횟수·완료의 네 열이다. 각 행 아래에 `지난 35kg × 10회`처럼 대응하는 지난 완료 세트를 표시한다. 같은 종목의 가장 최근 실제 운동에서 완료한 세트만 순서대로 대응한다. 현재 세트가 더 많으면 `지난 기록 없음`으로 표시하며 마지막 값을 반복하지 않는다. 맨몸 종목은 무게 대신 지난 횟수를 표시한다. 예시 보기 기록은 실제 입력의 참고 데이터에 섞지 않는다.
5. 세트 전체에서 처음 발견되는 미완료 세트 하나를 다음 세트로 약하게 강조한다. 사용자에게 해당 세트를 강제하지 않고 다른 세트도 바로 입력·완료할 수 있다. 완료를 취소하면 기존 값을 유지하고 다시 편집할 수 있다. 상태 전환에 행 높이·스크롤·포커스를 바꾸지 않는다.
6. 세트 추가는 종목 바로 아래, 운동 추가와 메모는 종목 목록 아래에 둔다. `운동 마치고 저장` 하단 고정 CTA와 완료한 세트만 저장하는 규칙을 유지한다.

### 준비 화면과 상태

선택된 구성 → 최근 운동 최대 3개 → 추천 루틴 선택 진입과 내 루틴 → 하단 고정 CTA 순서로 정돈한다. 기존 기본 자유 운동과 별도 루틴 화면·선택 취소를 유지한다. 추천 테마는 접힘 영역으로 유지하여 초기 화면을 길게 만들지 않는다. 선택한 운동에 기존 항목을 적용하면서 필수 입력을 추가하지 않는다.

종목 없는 진행 화면의 바로 추가 목록은 유지한다. 긴 종목 이름은 어절 단위로 줄바꿈하고 관리 버튼 영역을 보존한다. 읽기 오류·저장 실패·재시도·완료 결과·초안 복원은 기존 동작을 유지한다. 준비·진행·휴식·저장에는 광고를 넣지 않는다.

### 수치와 완료 기준

본문 15px 이상, 숫자 입력 16px 이상, 보조 정보 13px 이상, 터치 영역 44px 이상, font-weight 400~700, CTA safe area 34px를 유지한다. 기록 스키마·저장 키·기본 값·검증 범위는 변경하지 않는다. 완료 체크는 추가 확인 없이 한 번, 세트 추가는 한 번이며 시작·저장에 새 단계가 없다. 종목 관리와 추천 테마 탐색에는 영역을 여는 한 번의 탭이 추가된다. 자유 운동·최근 운동 시작과 반복 세트 입력은 조작 수를 늘리지 않는다.

320×740·390×844에서 입력·완료·세트 추가·휴식 전환·키보드·관리·삭제 취소·새로고침·저장 결과를 검증한다. 실제 토스 키보드·플랫폼 뒤로가기·safe area 검증은 실기기 결과와 구분해 기록한다.

## Strong 시각 디자인 적용 (2026-10-03)

사용자가 기존 컴포넌트의 부조화를 지적하고 TDS 필수 사용 조건을 해제했다. [Strong App Re-Design Concept](https://dribbble.com/shots/21768093-Strong-App-Re-Design-Concept)의 어두운 캔버스·차콜 카드·라임 강조·작은 아이콘을 기준으로 진행 화면을 수정했다. 원본 로고·사진·이미지 자산은 사용하지 않았다.

- 시간·완료 세트는 한 줄에 둔다. 숫자 입력은 17px, 보조 정보는 13px, 제목은 22px다.
- 종목 관리는 44px 아이콘 버튼이며 접근성 이름·펼침 상태와 Escape/포커스 복귀를 유지한다.
- 휴식 영역은 대기·진행 모두 62px로 유지한다. 완료 숫자와 체크는 라임색, 다음 세트는 약한 색면으로 구분한다.
- 준비는 기존 밝은 탐색 화면에 차콜 선택 구성 카드·라임 CTA를 적용한다. 루틴 선택·종목 선택·결과 시트는 기존 밝은 화면을 유지한다.
- 운동 시작·저장은 자체 하단 CTA이며 루틴 확정은 기존 TDS BottomCTA다. 플랫폼 네비게이션·저장 모델과 광고 조건은 바꾸지 않는다.

## 화면 밀도 조정 (2026-10-03)

큰 컴포넌트 때문에 세트 전체를 훑기 어렵다는 사용자 피드백을 반영했다. 요약 카드와 중복 라벨을 제거하고 휴식 상태·설정 선택·30초 연장·건너뛰기를 62px 한 줄로 묶었다. 선택 컨트롤은 차콜 배경과 SVG 꺾쇠를 사용하고 기존 끄기/60/90/120초 값을 유지한다. 건너뛰기/닫기는 접근성 이름을 제공하는 44px 아이콘 버튼이다.

카드 여백과 행 사이 간격을 줄여 세트 행 높이는 74px, 주요 CTA는 48px다. 숫자 입력·체크·관리·선택은 44px 터치 영역을 유지한다. 320×740에서 기본 3세트가 CTA 위에 모두 보이는 것을 확인했다. 기록과 휴식 동작의 추가 탭·화면 전환은 없다.

## 색상 통일과 휴식 선택 패널 (2026-10-03 최신 지시)

차콜·라임 테마는 사용자 피드백에 따라 흰 배경·중립색·blue로 교체했다. 기존 밀도와 자체 컴포넌트는 유지한다. 운동 진행·준비·하단 CTA·탭·완료 상태는 공통 색상 변수를 사용한다. 이전 차콜·라임 설명은 이 변경 전 기록이다.

휴식 설정은 네이티브 select 대신 44px 버튼과 작은 선택 패널을 사용한다. 끄기/60/90/120초 선택은 즉시 적용하고 패널을 닫아 버튼에 포커스를 돌린다. 현재 값은 blue로 구분하고 펼침 상태·선택 상태를 접근성 속성으로 제공한다. Escape·바깥 클릭·포커스 이탈로 닫히며 화면 이동·자동 재개·추가 확인은 없다. 패널은 본문 위치를 밀지 않는다.


## 앱 전체 운동 이어하기와 공유 휴식 (2026-10-03)

진행 초안이 있으면 운동 화면을 제외한 모든 페이지의 하단에 작은 진행 바를 표시한다. 왼쪽은 운동명·경과 시간과 운동 이어하기, 오른쪽은 휴식 상태와 타이머 펼치기다. 홈의 중복 이어하기 CTA는 제거한다. 상세·종목 선택·인증 등 모달 안에서도 같은 바를 제공한다. 다른 기록의 수정 내용을 버리는 경우에만 기존 보호 확인을 유지한다. 인증 작성에서 돌아올 때 아래의 기록 상세도 닫는다.

하단 탭이 있으면 탭 위, 하위 페이지에서는 safe area 위, 루틴 선택에서는 기존 CTA 위에 배치하고 본문 스크롤 여백을 확보한다. 펼친 휴식 패널은 명시적으로 누를 때만 나타나고 화면 진입이나 세트 완료로 자동 팝업을 띄우지 않는다. 입력과 세트 완료의 탭 수는 늘지 않으며 다른 화면에서는 한 번의 탭으로 운동에 복귀한다.

Strong의 세트 완료 후 자동 시작·연장·건너뛰기와 Hevy의 기본값/종목별 설정 구분 및 진행 중 운동 접근 패턴을 참고한다. [Strong 휴식 타이머](https://help.strongapp.io/article/231-rest-timer), [Hevy 휴식 설정](https://help.hevyapp.com/hc/en-us/articles/35385404949143-Rest-Timer-Default-Rest-Timer-How-to-Add-Adjust-Volume-and-Sound), [Hevy 진행 중 운동 접근](https://help.hevyapp.com/hc/en-us/articles/35649846517399-How-to-Use-Hevy-s-Live-Activity-on-iOS-and-Android).

휴식 컨트롤은 운동 화면과 공통 바에서 같은 상태·동작을 사용한다. 끄기/60/90/120초는 다음 휴식의 기본 설정, +30초는 현재 타이머 조정이다. 기본 시간을 바꿔도 진행 중인 종료 시각이나 루틴 종목별 시간은 덮어쓰지 않는다. 끄기는 현재 타이머를 해제하고 종목별 설정보다 우선한다. 수동 시작은 기본 시간, 세트 완료 자동 시작은 종목별 시간 또는 기본 시간을 사용한다. 끝난 휴식의 +30초는 현재 시각부터 30초를 더한다.

기존 초안의 종료 시각을 저장하고 앱의 공통 상태에서 계산하므로 탭 이동·새로고침 뒤에도 동일한 남은 시간을 표시한다. 저장한 운동이 끝나면 진행 바와 타이머가 사라진다. OS 라이브 액티비티·알림·소리·진동은 이번 구현 범위가 아니다.
