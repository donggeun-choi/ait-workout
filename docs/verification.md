# 구현 검증

## 기록 신뢰성과 최근 운동 재사용 (2026-10-03)

검증 환경: 별도 managed worktree, origin 5193, 자동화 브라우저 세션 recording-5193. 실제 사용자 저장소는 사용하지 않았다.

전체 검증: 단위 테스트 12개, ESLint, TypeScript, 웹 빌드, `.ait` 생성 통과. 기존 큰 웹 번들 경고는 유지된다.

독립 코드 리뷰: 저장 상태·완료 저장 중 입력 차단·중복 쓰기 억제·초안 보호·실제 기록 복사를 검토했고 병합 차단 결함 없음. 테스트 12개 재실행 통과. 지연 완료 저장과 탭 이동을 함께 재현하는 자동 React 통합 테스트는 후속 보강 권장이다.

이번 작업의 판단과 한계:

- 원본 checkout 보호를 위해 managed worktree를 사용했다. 결과는 별도 브랜치에 있으므로 원본 반영은 병합 단계에서 진행한다.
- 기존 테마 버튼을 44px로 보강했다. 준비 화면의 해당 버튼 영역 높이는 조금 늘어난다.
- 전체 검사 성공 이후 문서만 수정한 단계는 빌드를 반복하지 않고 diff 검사로 확인했다.
- 커뮤니티·로그인·내 루틴 CRUD·기록 편집은 이 첫 단계 범위 밖이다. 기능 제공으로 표시하지 않는다.
- 실제 토스 기기 실패·키보드·뒤로가기는 브라우저 증거만으로 완료 판단하지 않는다.
- 서로 다른 브라우저 창의 동시 편집 충돌은 기존 저장소의 별도 문제다. 이번 완료 저장 중 탭 이동 검증은 앱 내부 메뉴 이동이다. 여러 창에서 동시에 기록할 때 충돌 보호를 보장하지 않는다.
- 외부에서 작성한 세션의 빈 종목은 현재 가져오기 기능이 없고 앱 저장 시 제거하므로 추가 보정하지 않았다. 향후 가져오기 기능에서 검증해야 한다.

- 자동 저장 실패를 Storage 포트에 주입: 60kg·8회 입력 유지, 오류 안내, 추가 입력 없이 재시도, 새로고침 후 복원.
- 완료 저장 실패: 완료 세트와 초안 유지, 완료 시트 미노출. 초안 저장 재시도 후 완료 저장 성공. 쓰기 호출은 실패 완료→초안 재시도→성공 완료이며 결과 반영 후 중복 자동 쓰기 없음.
- 손상 문자열로 초기 읽기 실패: 시작 CTA 비활성, 원본 문자열 그대로 유지. 검증 백업으로 복원 후 정상 재진입.
- 실제 기록 선택 1탭→시작 CTA 1탭. 60kg×8회 초기값 복사, 완료 0세트·빈 메모·새 시작 시각. 새로고침 후 초안 유지.
- 복사값을 62.5kg로 수정, 홈→이어하기에서 유지, 저장 후 원본 60kg 기록과 새 62.5kg 기록 독립. 완료 2세트·총 운동량 980kg 반영.
- 루틴 선택 취소 후 기존 최근 운동 선택 유지. 과거 응답이 최신 저장 상태를 바꾸지 않는 단위 테스트 통과.
- 390×844·320×740에서 가로 넘침 없음, 검사한 텍스트 11px 이하 없음. 준비 화면의 기존 테마 버튼을 최소 44px로 보강했고 전체 버튼 높이 검사에서 44px 미만 없음.
- 저장 상태 갱신 후 숫자 입력 포커스 유지. 콘텐츠 main과 CTA·하단 탭의 경계 확인. 브라우저 오류 로그 없음.

캡처: `docs/screenshots/recording-foundation/`. 개발용 AIT 패널 버튼이 포함되므로 등록용 이미지가 아니다. 검증용 장애 주입은 브라우저 런타임에만 적용했고 새로고침으로 제거했다. 실제 토스 앱 키보드·뒤로가기·네이티브 저장 실패 검증은 남는다.

조작 비교: 기존 홈→운동 준비 1탭과 자유 운동 시작 1탭 유지. 준비에서 최근 운동 재사용은 선택 1탭+시작 1탭이며 반복 종목 검색·값 입력이 생략된다. 자동 저장에는 추가 탭 0회, 일상 세트 완료에는 확인창 0개. 실패 시에만 재시도 버튼 제공.

## 전체 개인 기능·서버 커뮤니티 (2026-10-03)

최종 구현은 4탭과 별도의 SQLite 커뮤니티 서버다. 개인 기록·루틴·설정은 기존 기기 저장소를 유지한다. 최종 `bash scripts/check.sh`: 35개 테스트, ESLint(서버/운영 JS 포함), TypeScript, 웹 빌드, `.ait` 생성 성공. 번들 크기 경고는 남으며 출시 전 로딩 성능은 실제 기기에서 확인한다.

별도 화면 origin 5196/5197과 테스트 DB/API 5198에서 확인했다. 사용자 화면 5193의 기록을 테스트 데이터로 변경하지 않았다.

- 최근 기록·내 루틴 선택 후 BottomCTA로 시작, 기본 세트·순서, 지난 값, 90초 완료 휴식·+30초와 새로고침 복원을 확인했다.
- 완료 저장→기록 수정 40→60kg(10회)의 600kg 재계산·재진입과 JSON 병합의 기존 기록 보존·맨몸20회 추가·복원 직전 백업을 확인했다. 별도 통합 화면에서 60kg×8회=480kg 기록을62.5kg로 수정해500kg을 확인했다.
- 편집 중 브라우저 뒤로가기 확인을 취소해 입력62.5와 원본60, 열린 기록 모달, history.sheet를 유지했다. 루틴 작성의 뒤로가기 취소도 이름과 화면을 유지했다.
- 개인 메모가 있는 실제 테스트 기록에서 인증 작성 진입·닫기 시 상세 복귀·게시 성공 후 내 인증 이동을 확인했다. 기본 요청은 날짜(한국 시간10/03)·종목/세트 수·선택 소감·전부 꺼진 공개 옵션뿐이며 이름·무게·횟수·개인 메모는 보내지 않았다. 게시 후 원본 기록과 메모는 유지됐다.
- 실제 로컬 API로 타 계정 인증을 만들고 응원0→1, 자기 응원 비활성, 신고를 확인했다. 최초 로그인 후 신고 이전 피드 응답을 의도적으로 지연해 신고 성공 뒤 전달했을 때 신고 대상은 숨기고 다른 인증은 유지했다. 이 검증은 테스트용 fetch 지연이며 토스 운영 인증 검증이 아니다.
- 실제 브라우저 관리자 화면에서 토큰으로 신고 조회→숨김→처리 완료→완료 목록 선택→복구를 확인했다. API 자체 출처의 PATCH가 성공했고 처리/복구 버튼에 막다른 경로가 없다.
- 320×740·390×844 캡처에서 4탭과 콘텐츠를 확인했다. 문서 가로 폭320, 가로 넘침없음,11px 이하 텍스트없음, 표시 버튼44px 이상, 커뮤니티 광고0개. 숫자는 본문 폰트, 이모지는 Tossface의 유효 Unicode 범위로 배선했다. 캡처는 `screenshots/complete/`이며 개발 AIT 버튼을 포함하므로 등록용 이미지가 아니다.

독립 리뷰에서 계정 변경 후 이전 게시/탈퇴 실행, 제한 계정 탈퇴, UTF-8 청크, 한국 날짜, 관리자 출처와100개 초과 신고, 편집 취소 이력, 휴식 끄기와 피드 지연 응답을 점검·수정했다. 최종 재검토에 추가 P1/P2 지적없음. 저장/권한 테스트는 실질 실패 경로를 검증하며 커뮤니티 서버는 가짜 데이터로 동작하지 않는다.

실제 토스 mTLS 로그인·콜백, 네이티브 파일 저장·키보드·SafeArea·뒤로가기·화면 유지·햅틱, 운영 광고 노필/클릭 복귀, 콘솔 등록과 배포는 아직 검증하지 않았다. 운영 설정이 없으면 서버는 시작하지 않고 운영 광고 ID가 없으면 광고도 요청하지 않는다. 공개 운영은 `community-operations.md`의 외부 설정이 필요하다.

main 병합 후 같은 전체 check를 재실행해35개 테스트와 모든 빌드를 확인했다. 실행 중인 로컬 미리보기는5193, 별도 개발 API는5194이며 실제 사용자 origin에 테스트 게시물을 넣지 않았다. 내 루틴의 종목별90초 기본값이 있어도 진행 화면에서 기본 휴식을끄기로 바꾼 뒤 세트 완료 시 restUntil=null, 종목 restSeconds=0을 확인했고 초안이 있는 대시보드 광고는0개였다.

## 홈·운동 분석 통합 (2026-10-03)
