# 구현 검증

## 기록 신뢰성과 최근 운동 재사용 (2026-10-03)

검증 환경: 별도 managed worktree, origin 5193, 자동화 브라우저 세션 recording-5193. 실제 사용자 저장소는 사용하지 않았다.

전체 검증: 단위 테스트 12개, ESLint, TypeScript, 웹 빌드, `.ait` 생성 통과. 기존 큰 웹 번들 경고는 유지된다.

독립 코드 리뷰: 저장 상태·완료 저장 중 입력 차단·중복 쓰기 억제·초안 보호·실제 기록 복사를 검토했고 병합 차단 결함 없음. 테스트 12개 재실행 통과. 지연 완료 저장과 탭 이동을 함께 재현하는 자동 React 통합 테스트는 후속 보강 권장이다.

이번 작업의 판단과 한계:

- 원본 checkout 보호를 위해 managed worktree를 사용했다. 결과는 별도 브랜치에 있으므로 원본 반영은 병합 단계에서 진행한다.
- 기존 테마 버튼을 44px로 보강했다. 준비 화면의 해당 버튼 영역 높이는 조금 늘어난다.
- 전체 검사 성공 이후 문서만 수정한 단계는 빌드를 반복하지 않고 diff 검사로 확인했다.
- 커뮤니티·로그인·내 루틴 CRUD·기록 편집은 이 첫 단계 범위 밖이다. 기능 제공으로 표시하지 않는다.
- 실제 토스 기기 실패·키보드·뒤로가기는 브라우저 증거만으로 완료 판단하지 않는다.
- 서로 다른 브라우저 창의 동시 편집 충돌은 기존 저장소의 별도 문제다. 이번 완료 저장 중 탭 이동 검증은 앱 내부 메뉴 이동이다. 여러 창에서 동시에 기록할 때 충돌 보호를 보장하지 않는다.
- 외부에서 작성한 세션의 빈 종목은 현재 가져오기 기능이 없고 앱 저장 시 제거하므로 추가 보정하지 않았다. 향후 가져오기 기능에서 검증해야 한다.

- 자동 저장 실패를 Storage 포트에 주입: 60kg·8회 입력 유지, 오류 안내, 추가 입력 없이 재시도, 새로고침 후 복원.
- 완료 저장 실패: 완료 세트와 초안 유지, 완료 시트 미노출. 초안 저장 재시도 후 완료 저장 성공. 쓰기 호출은 실패 완료→초안 재시도→성공 완료이며 결과 반영 후 중복 자동 쓰기 없음.
- 손상 문자열로 초기 읽기 실패: 시작 CTA 비활성, 원본 문자열 그대로 유지. 검증 백업으로 복원 후 정상 재진입.
- 실제 기록 선택 1탭→시작 CTA 1탭. 60kg×8회 초기값 복사, 완료 0세트·빈 메모·새 시작 시각. 새로고침 후 초안 유지.
- 복사값을 62.5kg로 수정, 홈→이어하기에서 유지, 저장 후 원본 60kg 기록과 새 62.5kg 기록 독립. 완료 2세트·총 운동량 980kg 반영.
- 루틴 선택 취소 후 기존 최근 운동 선택 유지. 과거 응답이 최신 저장 상태를 바꾸지 않는 단위 테스트 통과.
- 390×844·320×740에서 가로 넘침 없음, 검사한 텍스트 11px 이하 없음. 준비 화면의 기존 테마 버튼을 최소 44px로 보강했고 전체 버튼 높이 검사에서 44px 미만 없음.
- 저장 상태 갱신 후 숫자 입력 포커스 유지. 콘텐츠 main과 CTA·하단 탭의 경계 확인. 브라우저 오류 로그 없음.

캡처: `docs/screenshots/recording-foundation/`. 개발용 AIT 패널 버튼이 포함되므로 등록용 이미지가 아니다. 검증용 장애 주입은 브라우저 런타임에만 적용했고 새로고침으로 제거했다. 실제 토스 앱 키보드·뒤로가기·네이티브 저장 실패 검증은 남는다.

조작 비교: 기존 홈→운동 준비 1탭과 자유 운동 시작 1탭 유지. 준비에서 최근 운동 재사용은 선택 1탭+시작 1탭이며 반복 종목 검색·값 입력이 생략된다. 자동 저장에는 추가 탭 0회, 일상 세트 완료에는 확인창 0개. 실패 시에만 재시도 버튼 제공.

2026-10-01, 로컬 개발 서버와 별도 자동화 브라우저 프로필에서 확인했습니다.

## 기능

- 홈·운동·대시보드 탭 이동과 선택 상태 표시.
- 실제 기록이 없는 빈 상태, 별도 예시 데이터 보기.
- 상체 루틴 시작 → 벤치 프레스 60kg × 8회 완료 → 480kg 계산 → 운동 완료 → 상세 결과 → 홈 이동.
- 새로고침 후 저장된 기록 유지, 대시보드 1회·1세트·480kg 반영.
- 자유 운동 → 종목 검색 `스쿼트` → 종목 추가.
- 0회 입력 시 완료를 차단하고 입력 범위 안내.
- 올바른 횟수 입력 후 세트 완료 및 90초 휴식 표시.
- 주간 활동과 그래프는 월요일 기준.

## 화면

- 390 × 844 및 320 × 740 뷰포트에서 가로 넘침 없음.
- 검사한 화면의 11px 이하 텍스트 및 44px 미만 버튼 높이 없음.
- 하단 탭 34px 이상의 안전 여백, 본문 끝의 스크롤 공간 확보.
- 모달에 닫기 버튼 제공, 닫기 및 검색 동작 확인.
- 시스템 본문 폰트 적용, 메모의 이모지는 Tossface로 표시.
- 브라우저 오류 로그 없음.
- TDS Provider, Button, Badge, Asset.ContentIcon 사용. 브랜드 primary는 사용자가 명시한 블루 테마.

실기기에서 컨테이너 뒤로가기, 키보드에 따른 모달 위치, safe area는 아직 확인하지 않았습니다. 저장 공간 부족 및 손상 데이터 안내는 코드에서 처리하며, 브라우저 검증에서는 실제 저장 실패를 강제로 발생시키지 않았습니다. 네트워크 로딩 상태는 데이터가 동기 로컬 저장이므로 해당하지 않습니다. 등록용 이미지 자산 생성 및 콘솔 업로드는 이번 범위에 포함하지 않았습니다.

화면 캡처는 `docs/screenshots/`에 있으며 개발용 AIT 버튼이 포함되어 있습니다. 등록용 스크린샷이 아닙니다.

## 운동 화면 TDS 개편

- 운동 시작과 운동 저장은 TDS `BottomCTA.Single`로 하단 고정, 탭 위에 배치.
- 추천 루틴은 `#routines` 별도 화면에서 선택·구성 확인.
- `Top`, `ListRow`, `ListRow.Texts`, `Badge`, `TextArea`로 제목·목록·메모 대체.
- 하체 루틴 선택 후 운동 메인에 4개 운동·12세트가 반영되는 것을 실제 브라우저에서 확인.
- 루틴 선택은 임시 선택 후 CTA를 눌러 확정하며 돌아가기로 나가면 기존 선택 유지.
- 추천 루틴 화면에서는 하단 탭을 숨기고 선택 CTA를 제공.
- 세트별 숫자 입력과 완료 체크는 밀도 있는 기록 표를 위해 기존 사용자 정의 UI 유지.

## 공식 배너 슬롯 (2026-10-01)

별도 origin(5176)에서 devtools 배너 모형이 대시보드 통계 다음에 표시됨을 확인했다. 광고 영역은 position static, 너비 480px, 문서상의 상단 위치 1203px였다. 운동 화면으로 이동하면 제거되며, 자유 운동을 시작한 뒤 대시보드로 이동했을 때 광고 슬롯 수는 0이었다. 이 확인은 SDK mock 검증이며 실제 광고 요청·수익·노필 동작은 콘솔 QR 기기 검증이 필요하다. 운영 ID 없이 만든 빌드에는 광고를 부착하지 않는다.

## 플랫폼 SDK 추가 연결 (2026-10-01)

저장소 단위 테스트 5개: 네이티브 우선, 검증 전 이관 금지, 네이티브 읽기 실패 시 웹 데이터로 자동 대체 금지, 쓰기 순서·실패 후 재시도, 브라우저 저장 경로. 별도 origin 5178의 SDK mock 환경에서 자유 운동 시작 → 종목 추가 → 세트 완료 → 새로고침 후 완료 세트·휴식 복원 → 비동기 완료 저장 → 홈 기록 표시를 확인했다. 린트·타입·웹/.ait 빌드도 통과했다. 실제 네이티브 저장소의 이관, SafeArea 변화, 화면 꺼짐 방지와 진동 효과는 기기 검증이 남는다.
